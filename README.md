# Proxmox homelab (OpenTofu + NixOS)

Declarative VMs on Proxmox VE:

- **NixOS VMs**: any number of them, each defined by an entry in `nixos_vms` plus a
  NixOS config in `nixos/hosts/<name>/`. Tofu clones a Debian cloud image, and
  [nixos-anywhere](https://github.com/nix-community/nixos-anywhere) replaces it with
  NixOS (disko partitioning, static IP, SSH keys). Shared features:
  - **TLS**: Let's Encrypt via the Cloudflare **DNS-01** challenge for any VM with a
    `domain`, with no ports exposed to the internet.
  - **Backups**: nightly restic to Cloudflare R2, one repository per VM.
- **Kubernetes (k3s)**: a NixOS host type with declarative apps, one namespace each.
- **Home Assistant OS VMs**: the official appliance image, with optional USB passthrough.

Included NixOS hosts:

| Host | What |
|---|---|
| `authentik` | identity provider (PostgreSQL, nginx) |
| `k3s` | single-node k3s with **Pi-hole**, **Audiobookshelf** and **Mealie**, one namespace each |
| `kasm` | **Kasm Workspaces** (browser-streamed desktops/apps in Docker) |

## Layout

```
.
├── versions.tf             providers (bpg/proxmox, local)
├── variables.tf            Proxmox connection, shared defaults, TLS, backups, VM maps
├── main.tf                 one module instance per entry in nixos_vms / haos_vms
├── images.tf               Debian bootstrap image, HAOS images (on the PVE host)
├── backup.tf               nightly Proxmox backup job for all VMs
├── pve-tls.tf              Let's Encrypt certificate for the Proxmox web UI
├── outputs.tf              per-VM IDs, IPs, URLs, rebuild commands
├── moved.tf                state moves from the old single-VM layout
├── terraform.tfvars        your values (gitignored), see terraform.tfvars.example
├── .env                    secrets for tofu (gitignored), see .env.example
├── modules/
│   ├── nixos-vm/           Proxmox VM + settings.json + nixos-anywhere install
│   └── haos-vm/            Proxmox VM for Home Assistant OS, USB mappings, static IP
├── nixos/                  one flake for all NixOS hosts
│   ├── flake.nix           every hosts/<name>/ becomes nixosConfigurations.<name>
│   ├── flake.lock          pins nixpkgs, disko, authentik-nix
│   ├── modules/            shared by every host
│   │   ├── common.nix      boot, static network, SSH, nix settings
│   │   ├── disk-config.nix disko layout (/dev/sda, GPT, ext4)
│   │   ├── acme.nix        Let's Encrypt via DNS-01 for settings.domain
│   │   ├── backup.nix      homelab.backup.* options → pg_dump + restic to R2
│   │   └── k3s.nix         homelab.k3s.* options → k3s + declarative apps
│   └── hosts/
│       ├── authentik/
│       │   ├── default.nix       the host's own config
│       │   └── settings.json     generated by tofu (gitignored)
│       ├── k3s/
│       │   ├── default.nix       enables k3s, imports every file in apps/
│       │   └── apps/             one app = one namespace
│       │       ├── pihole.nix
│       │       ├── audiobookshelf.nix
│       │       └── mealie.nix
│       └── kasm/
│           └── default.nix       Kasm Workspaces (services.kasmweb, Docker)
└── scripts/
    └── rebuild.sh          apply NixOS changes to an existing VM
```

## Prerequisites (on the machine running tofu)

- **OpenTofu** >= 1.6, and `jq`.
- **Nix with flakes**, from the Fedora package. Its default `/etc/nix/nix.conf`
  already sets `experimental-features = nix-command flakes`:
  ```sh
  sudo dnf install nix-daemon
  sudo systemctl enable --now nix-daemon
  ```
  Allow the nix-community binary cache, or authentik gets built from source.
  Settings passed with `--option` are ignored for users not in `trusted-users`,
  so add the cache to the system config:
  ```sh
  sudo tee -a /etc/nix/nix.conf <<'EOF'
  extra-substituters = https://nix-community.cachix.org
  extra-trusted-public-keys = nix-community.cachix.org-1:mB9FSh9qf2dCimDSUo8Zy7bkq5CX+/rkCWyvRCYg3Fs=
  EOF
  sudo systemctl restart nix-daemon
  ```
  Check with `nix config show | grep substituters`.
- **SSH key in ssh-agent and authorized for root on the PVE node.** The provider
  imports disks over SSH, and the HAOS image is downloaded on the node over SSH. The
  provider only uses the agent and ignores `~/.ssh/config`:
  ```sh
  ssh-add ~/.ssh/id_ed25519
  ssh-copy-id root@<pve-host>
  ```
- **Proxmox API token**, created on the PVE host: `pveum user token add root@pam tofu --privsep 0`.
  `local` storage must allow the "ISO image" content type.

## Credentials

Secrets live in local files. Files for VMs are **copied at install time** (via
nixos-anywhere `--extra-files`, into `/var/lib/secrets/`, root-only), so they never
end up in tofu state, the Nix store or git.

| File | Contents | Used for |
|---|---|---|
| `.env` | `PROXMOX_VE_API_TOKEN=root@pam!tofu=...`<br>`TF_VAR_backup_r2_account_id=...` | Proxmox API, R2 account |
| `acme_dns_env_file` | `CLOUDFLARE_DNS_API_TOKEN=...` | Let's Encrypt DNS-01 |
| `backup_env_file` | `AWS_ACCESS_KEY_ID=...`<br>`AWS_SECRET_ACCESS_KEY=...` | R2 (S3 API) |
| `backup_password_file` | random restic repository password | backup encryption |

Keep the files `chmod 600`. **Store the restic password in your password manager.**
Without it, the backups can't be decrypted.

- **Cloudflare DNS token** (My Profile → API Tokens → Create Token): Zone → DNS → **Edit**
  and Zone → Zone → **Read**, limited to your zone.
- **R2**: create the bucket first. Then go to R2 → Manage R2 API Tokens → **Account API
  token**, choose *Object Read & Write*, limit it to that bucket, and set TTL *Forever*.
  Use the Access Key ID and Secret Access Key, not the "token value". The account ID is
  on the R2 overview page.

## Usage

```sh
cp terraform.tfvars.example terraform.tfvars    # and .env.example → .env
set -a; source .env; set +a                     # OpenTofu does not read .env by itself
tofu init
tofu apply
tofu output                                     # IPs, URLs, rebuild commands per VM
```

A NixOS install takes about 5–15 minutes per VM. The VM reboots into NixOS when it's
done. After the first apply, set `guest_agent = true` for the VM and apply again, so
Proxmox backups can freeze the filesystem.

`tofu destroy` deletes all VMs and their data.

## Adding a NixOS VM

1. Add an entry to `nixos_vms` in `terraform.tfvars`:
   ```hcl
   nixos_vms = {
     authentik = { ... }
     grafana = {
       ipv4_cidr = "192.0.2.60/24"
       memory_mb = 2048
       domain    = "grafana.example.com"   # optional: TLS cert + DNS-01
     }
   }
   ```
2. Create `nixos/hosts/grafana/default.nix`:
   ```nix
   { settings, ... }:
   {
     system.stateVersion = "26.05";   # set once, never change on an existing host

     services.grafana = {
       enable = true;
       settings.server.http_addr = "127.0.0.1";
     };
     services.nginx = {
       enable = true;
       virtualHosts.${settings.domain} = {
         enableACME = true;            # cert comes from modules/acme.nix (DNS-01)
         forceSSL = true;
         locations."/".proxyPass = "http://127.0.0.1:3000";
       };
     };
     networking.firewall.allowedTCPPorts = [ 80 443 ];

     homelab.backup.paths = [ "/var/lib/grafana" ];   # → R2 <bucket>/grafana
   }
   ```
3. Run `tofu apply`.

What every host gets from `nixos/modules/`: static networking and SSH keys from
`settings.json`, the guest agent, nix GC, and, if configured, the ACME cert for its
`domain` and restic backups of whatever it lists in `homelab.backup`. Extra per-VM
values can be passed through `settings = { key = "value" }` in `nixos_vms` and read as
`settings.key` in Nix.

## Kubernetes (k3s) and apps

The `k3s` host runs single-node [k3s](https://k3s.io) natively on NixOS, with its
bundled Traefik ingress and ServiceLB, which exposes `LoadBalancer` services on the
VM's own IP. Enable it with an entry in `nixos_vms`:

```hcl
nixos_vms = {
  k3s = {
    ipv4_cidr   = "192.0.2.60/24"
    cores       = 4
    memory_mb   = 4096
    disk_gb     = 40
    domain      = "k3s.example.com"         # optional: HTTPS for <app>.k3s.example.com
    dns_servers = ["1.1.1.1", "9.9.9.9"]   # never Pi-hole itself, or it can't start
  }
}
```

**HTTPS:** with a `domain` (and `acme_email`), the host obtains one Let's Encrypt
certificate for `<domain>` **and `*.<domain>`** via DNS-01. A systemd service copies
it into k3s after every renewal (`kube-system/homelab-tls`), and it becomes **Traefik's
default certificate**. Any Ingress with a `tls` section for `<app>.<domain>` is then
served over HTTPS with no per-app setup. The Kubernetes API certificate also accepts
`<domain>`. You need DNS for `<domain>` and `*.<domain>` pointing at the VM: either a
DNS-only (grey cloud) Cloudflare A record for each, or the local records Pi-hole serves
(below) for clients that use Pi-hole.

**Apps are declarative.** Every `*.nix` file in `nixos/hosts/k3s/apps/` is imported
and declares one app, with its own namespace, via `homelab.k3s.apps.<name>`:

- `manifests`: Kubernetes objects written as Nix attribute sets. `metadata.namespace`
  defaults to the app's namespace, and the Namespace object is created automatically.
- `charts`: Helm charts (HelmChart resources via `services.k3s.autoDeployCharts`).

NixOS writes them into k3s's auto-deploy directory, and k3s applies them. To add an app,
create `nixos/hosts/k3s/apps/<name>.nix` and run `./scripts/rebuild.sh k3s`:

```nix
# nixos/hosts/k3s/apps/whoami.nix
{
  homelab.k3s.apps.whoami.manifests = [
    {
      apiVersion = "apps/v1";
      kind = "Deployment";
      metadata.name = "whoami";
      spec = {
        selector.matchLabels.app = "whoami";
        template = {
          metadata.labels.app = "whoami";
          spec.containers = [{ name = "whoami"; image = "docker.io/traefik/whoami:v1.10"; }];
        };
      };
    }
    {
      apiVersion = "v1";
      kind = "Service";
      metadata.name = "whoami";
      spec = { selector.app = "whoami"; ports = [{ port = 80; }]; };
    }
    {
      apiVersion = "networking.k8s.io/v1";
      kind = "Ingress";
      metadata.name = "whoami";
      spec.tls = [{ hosts = [ "whoami.k3s.example.com" ]; }];   # default wildcard cert
      spec.rules = [{
        host = "whoami.k3s.example.com";
        http.paths = [{
          path = "/"; pathType = "Prefix";
          backend.service = { name = "whoami"; port.number = 80; };
        }];
      }];
    }
  ];
}
```

A Helm chart instead (get `hash` by setting `lib.fakeHash` first and copying the
correct value from the build error):

```nix
{ lib, ... }:
{
  homelab.k3s.apps.myapp.charts.myapp = {
    repo = "https://charts.example.com";   # the chart's Helm repository
    name = "myapp";                        # chart name in that repo
    version = "1.2.3";                     # chart version
    hash = lib.fakeHash;
    values = { service.type = "LoadBalancer"; };
  };
}
```

Notes:

- **Secrets don't belong in `manifests` or `values`**, because those end up in the
  world-readable Nix store. Generate them on the VM instead (see the Pi-hole admin
  password in `apps/pihole.nix`) or create them with `kubectl`.
- **Removing an app** deletes its manifest file, but k3s keeps the objects. Run
  `kubectl delete namespace <ns>` to remove them.
- **PersistentVolume data** (`/var/lib/rancher/k3s/storage`, local-path provisioner)
  is included in the R2 backup.
- **kubectl from your workstation:**
  ```sh
  ssh root@<vm-ip> cat /etc/rancher/k3s/k3s.yaml | sed 's/127.0.0.1/<vm-ip>/' > ~/.kube/k3s.yaml
  export KUBECONFIG=~/.kube/k3s.yaml; kubectl get pods -A
  ```
  Or on the VM: `k3s kubectl get pods -A`.

### Pi-hole

| | |
|---|---|
| DNS | `<vm-ip>:53` (UDP and TCP) |
| Web UI | `https://pihole.<domain>/admin/` (Traefik, Let's Encrypt); `http://<vm-ip>:8080/admin/` only if the VM has no domain |
| Local DNS | answers `<domain>` and `*.<domain>` with the VM's IP |
| Password | `ssh root@<vm-ip> cat /var/lib/pihole-secret/password` (generated on first boot) |
| Data | PVC `pihole-data` in namespace `pihole` |
| Image | pinned in `apps/pihole.nix`; bump the tag and rebuild to update |

To use it for your network, set your router's **DHCP DNS server** to the VM's IP.
Keep the router's own upstream DNS and the k3s VM's `dns_servers` pointed at public
resolvers, so nothing depends on Pi-hole to start Pi-hole.

### Audiobookshelf

| | |
|---|---|
| Web UI | `https://audiobookshelf.<domain>/`; `http://<vm-ip>:13378/` only if the VM has no domain |
| Login | the first visit creates the root user |
| Data | PVCs `audiobookshelf-config` and `audiobookshelf-metadata` (backed up) |
| Media | `/srv/audiobookshelf/{audiobooks,podcasts}` on the VM (hostPath, **not** backed up) |
| Image | pinned in `apps/audiobookshelf.nix` |

The media library is deliberately outside the k3s storage directory, so it doesn't
get uploaded to R2. Copy books in with `rsync`/`scp` to the VM, or replace the
`hostPath` volumes with an `nfs` volume pointing at your NAS. Add the folders as
libraries in the UI (`/audiobooks`, `/podcasts`). The VM's `disk_gb` limits how much
fits locally.

### Mealie

| | |
|---|---|
| Web UI | `https://mealie.<domain>/`; `http://<vm-ip>:9000/` only if the VM has no domain |
| Login | `changeme@example.com` / `MyPassword` on first start: **change both right away** |
| Sign-up | disabled; invite users from the admin settings |
| Data | PVC `mealie-data` (SQLite + images, backed up) |
| Image | pinned in `apps/mealie.nix` |

## Kasm Workspaces

The `kasm` host runs [Kasm Workspaces](https://kasmweb.com) with the NixOS
`services.kasmweb` module: the Kasm services are Docker containers, and the Kasm
agent starts each user session (Firefox, a desktop, ...) as another container on the
same VM. Workspace images are several GB each, and every session needs 1–2 GB RAM, so
give it room:

```hcl
nixos_vms = {
  kasm = {
    ipv4_cidr = "192.0.2.70/24"
    cores     = 4
    memory_mb = 8192
    disk_gb   = 100
    domain    = "kasm.example.com"   # optional: Let's Encrypt cert instead of self-signed
  }
}
```

| | |
|---|---|
| Web UI | `https://<domain>/` (Let's Encrypt), or `https://<vm-ip>/` (self-signed) |
| Admin | `admin@kasm.local`, password: `ssh root@<vm-ip> cat /var/lib/kasmweb-secrets/admin-password` |
| User | `user@kasm.local`, password in `/var/lib/kasmweb-secrets/user-password` |
| Backups | nightly `pg_dump` (02:00) to `/var/backup/kasm`, plus the generated secrets and server IDs |
| Version | `pkgs.kasmweb` from nixpkgs (1.15) |

- The passwords and the internal manager/guac/registration tokens are **generated on
  the VM** at first boot and read by the init script at runtime, so they're not in the
  Nix store. The passwords only seed the database: change them in the UI afterwards
  if you like.
- **First start takes a while**: `init-kasmweb` waits until the database is seeded
  before it starts the proxy. Follow it with `journalctl -fu init-kasmweb`.
- After the first login, go to Admin → Workspaces → Registry and install the
  workspaces you want; each one is pulled as a Docker image on first use.
- The Kasm version follows nixpkgs, so it only changes when you update `nixpkgs` and
  rebuild. Major Kasm upgrades may need a database migration; check the release notes.

## Adding a Home Assistant OS VM

```hcl
haos_vms = {
  homeassistant = {
    haos_version = "18.4"                 # release with a haos_ova-<ver>.qcow2.xz asset
    memory_mb    = 4096
    mac_address  = "BC:24:11:00:00:01"    # optional, fixed MAC
    ipv4_cidr    = "192.0.2.57/24"        # optional static IP (default: DHCP)
    usb_devices = {                       # optional passthrough (see `lsusb` on the PVE host)
      zigbee-zwave = "10c4:8a2a"
      bluetooth    = "0b05:1bf6"
    }
  }
}
```

What tofu does:

1. Downloads `haos_ova-<version>.qcow2.xz` **on the PVE host over SSH** and unpacks it
   (Proxmox can't decompress `.xz` itself). One image per distinct version.
2. Creates a USB **resource mapping** per device, named `<vm>-<label>`. Proxmox only lets
   `root@pam`, not API tokens, attach raw host USB devices, but tokens can use mappings.
3. Creates a UEFI (OVMF, no Secure Boot) q35 VM with the guest agent enabled, and
   imports the image as its disk.
4. With `ipv4_cidr`: HAOS has no cloud-init, so `modules/haos-vm/set-network.sh` runs
   `ha network update … --ipv4-method static` **inside the VM through the guest agent**
   (Proxmox API `agent/exec`). This uses the Supervisor's supported network API and
   persists across reboots and updates.

The `haos_vms` output shows the URL (static IP, or the DHCP address from the guest agent).
The VM is automatically part of the nightly Proxmox backup job.

**Migrating from an existing HA VM:**

1. Make and download a full backup in the old HA. Check that the download completed.
2. Shut down the old VM and disable its autostart, because both VMs can't use the USB
   devices at once.
3. Set `usb_devices` for the new VM and run `tofu apply`. The provider restarts the VM
   with the devices attached.
4. Open `http://<ip>:8123`, choose **Restore from backup** and upload the file. If the
   page appears stuck, check `ha jobs info`; the restore often finishes before the page
   notices.
5. Keep the old VM stopped as a fallback (and out of the backup job via `extra_vmids`)
   until you're happy, then delete it.

**HTTPS and off-site backups (inside HA, not managed by tofu).** HAOS has no NixOS ACME
module, so TLS comes from HA's own apps. Set this up **after** restoring a backup,
because a restore overwrites it:

- **Let's Encrypt** app: `challenge: dns`, `dns.provider: dns-cloudflare`,
  `dns.cloudflare_api_token`, `domains: [<fqdn>]`. It writes `/ssl/fullchain.pem` and
  `/ssl/privkey.pem`.
- **NGINX SSL proxy** app: `domain: <fqdn>`, which serves HTTPS on port 443. Port 8123
  stays plain HTTP, so `https://<fqdn>:8123` fails with "SSL record too long".
- **Reverse proxy setting:** recent HA versions keep HTTP settings in the UI, not
  `configuration.yaml` (a YAML `http:` block is ignored). Go to Settings → System →
  Network → HTTP → Reverse proxy, enable **Trust X-Forwarded-For**, set **Trusted
  proxies** to `172.30.33.0/24`, save, and **confirm** after the restart; otherwise
  HA reverts the change automatically. Until this is set, the proxy gets HTTP 400.
- **Renewal:** an automation runs `hassio.app_start: core_letsencrypt` weekly (the app
  renews when the certificate is due), then `hassio.app_restart: core_nginx_proxy`.
- **Off-site backups:** HA's built-in automatic backups (daily, encrypted) plus the
  **Cloudflare R2** integration as a backup location: endpoint
  `https://<account-id>.r2.cloudflarestorage.com`, the same bucket, prefix
  `homeassistant`. Enable it under Settings → System → Backups → Locations.

- HAOS **updates itself** (OS, Supervisor, Core and add-ons) from its web UI.
  `haos_version` only matters for the first install.
- A USB device can only be used by **one running VM**. When migrating from an existing
  HA VM, stop it first, then restore a HA backup during onboarding.
- Not every HAOS release ships VM images; for example, some patch releases are
  Raspberry Pi only. Check the
  [release assets](https://github.com/home-assistant/operating-system/releases).

## Changing a NixOS VM later

The install step runs **once per VM** because it wipes the disk. It is not
re-triggered by config changes. To roll out changes:

```sh
tofu apply                          # only if tfvars/.env changed (regenerates settings.json)
./scripts/rebuild.sh <host>         # build locally, activate over SSH
./scripts/rebuild.sh <host> test    # activate without making it the boot default
```

**New secrets on an existing VM** are not copied automatically, because that only
happens during install. Copy them by hand before rebuilding:

```sh
scp <local-file> root@<vm-ip>:/var/lib/secrets/<name>
ssh root@<vm-ip> 'chmod 600 /var/lib/secrets/*'
```

## Upgrades

Nothing upgrades automatically. Every version is pinned in `nixos/flake.lock`, and
a VM only changes when you rebuild it.

- **OS packages and security fixes** (`nixpkgs`, `nixos-26.05`):
  ```sh
  (cd nixos && nix flake update nixpkgs)
  ./scripts/rebuild.sh <host>      # for each NixOS host
  ```
- **authentik** (`authentik-nix`, which pins its own nixpkgs): its database
  migrations **cannot be undone**, so take a Proxmox snapshot of the VM first:
  ```sh
  (cd nixos && nix flake update authentik-nix)
  ./scripts/rebuild.sh authentik
  ```
  Check that authentik works, then delete the snapshot.

If an update breaks a host, run `nixos-rebuild switch --rollback` on it, or choose the
previous generation in the GRUB menu.

## Backups

| Level | What | Where | When |
|---|---|---|---|
| App | per host: `homelab.backup.postgresql.databases` (dumped) + `homelab.backup.paths` | R2 `<bucket>/<vm name>` (restic, encrypted) | dump 02:00, upload ~03:00 (VM time zone) |
| HAOS | HA's own automatic backups (config, apps, database; encrypted) | local + R2 `<bucket>/homeassistant` (HA's Cloudflare R2 integration) | daily, set in HA |
| VM | full VM images of every VM in `nixos_vms`/`haos_vms` + `pve_backup.extra_vmids` | PVE storage `pve_backup.storage` | `pve_backup.schedule` (default 01:00, PVE host time zone) |

The app-level backup keeps 7 daily, 4 weekly and 6 monthly snapshots and verifies 5% of
the repository data after each run. Missed runs start at the next boot.

The Proxmox job (`homelab-nightly`, in `backup.tf`) is managed by tofu. It automatically
includes every VM defined here; add VMs that tofu doesn't manage via `extra_vmids`.
It uses snapshot mode, and with `guest_agent = true` the filesystems are frozen briefly
so databases are consistent on disk. Retention defaults to 3 daily and 2 weekly copies
per VM.

```hcl
pve_backup = {
  extra_vmids   = [100]                                    # e.g. a hand-made VM
  prune_backups = { "keep-daily" = "3", "keep-weekly" = "2" }
}
```

```sh
ssh root@<vm-ip> restic-r2 snapshots
ssh root@<vm-ip> systemctl status restic-backups-r2
ssh root@<vm-ip> systemctl start restic-backups-r2      # run now
```

**Restore authentik from R2** onto a fresh VM (`tofu apply` with the same settings),
then on the VM:

```sh
systemctl stop authentik authentik-worker
restic-r2 snapshots                         # wrapper with repo + credentials preset
restic-r2 restore latest --target /
sudo -u postgres psql -c 'DROP DATABASE authentik' -c 'CREATE DATABASE authentik OWNER authentik'
sudo -u postgres psql authentik < /var/backup/postgresql/authentik.sql
systemctl start authentik-migrate authentik authentik-worker
```

## Proxmox web UI certificate

With `pve_domain` (plus `acme_email` and `acme_dns_env_file`) set, `pve-tls.tf` uses
Proxmox's built-in ACME client to get a Let's Encrypt certificate for the web UI/API on
port 8006. It uses the Cloudflare DNS-01 plugin, so no ports are opened, and Proxmox
renews it automatically. The Cloudflare token goes to Proxmox as a **write-only**
attribute, so it is never stored in tofu state. After rotating the token, bump
`data_wo_version`. Setting `pve_acme_tos` means you agree to Let's Encrypt's terms.
Proxmox only lets `root@pam` itself register ACME accounts (API tokens are refused with
`Permission check failed (user != root@pam)`), so the account is registered over SSH as
root with `pvesh`. The DNS plugin and the certificate order use the API token.

After the first apply, add a DNS record for `pve_domain` pointing at the host, then switch
the provider to the name with full TLS verification:


## Troubleshooting

- **`hostname lookup 'pve' failed`**: `proxmox_node` must match the node's real name
  (see `pvesh get /nodes`).
- **`unable to authenticate user "root" over SSH ... attempted methods [none password]`**:
  the key isn't in ssh-agent (`ssh-add -l`) or not authorized on the PVE host.
- **`Unable to create Proxmox VE API credentials`**: `.env` wasn't loaded into this shell.
- **`No NixOS config for this VM`**: create `nixos/hosts/<name>/default.nix`.
- **Install step failed after NixOS was actually installed** (e.g. the script was
  interrupted after `### Done! ###`): tofu marks the VM's `terraform_data.install` as
  *tainted*, and the next apply would **reinstall and wipe the VM**. If the VM is fine:
  `tofu untaint 'module.nixos_vm["<name>"].terraform_data.install'`.
- **`https://<ha-fqdn>:8123` → "SSL received a record that exceeded the maximum
  permissible length"**: 8123 is plain HTTP. Use `https://<ha-fqdn>`, which goes through
  the NGINX SSL proxy on port 443.
- **HA behind the proxy returns HTTP 400**: the reverse-proxy setting isn't active. See
  the HTTPS notes in the Home Assistant section.
- **`Permission check failed (user != root@pam)`** when creating the Proxmox ACME account:
  only root's own login may register ACME accounts, which is why `pve-tls.tf` does it over SSH.
- **Guest agent changes** in Proxmox only take effect after a full stop and start from
  Proxmox, not after a reboot from inside the guest.
- **`settings.json` not found / host missing from the flake**: inside a git checkout,
  Nix only sees tracked files, and `settings.json` is gitignored so personal details stay
  out of the repo. Always reference the flake with `path:`, for example
  `--flake path:./nixos#<host>`. `install.sh` and `rebuild.sh` already do this.
